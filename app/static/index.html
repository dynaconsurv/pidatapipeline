How the PI Delivery Pipeline Works

This pipeline receives real-time telemetry pushed directly from AVEVA PI System Explorer via PI AF Notifications WebService REST Delivery Endpoints:

  • PI Delivery Ingestion Endpoint: PI Notifications sends HTTP POST requests to /api/v1/delivery containing real-time meter telemetry.
  • JSON Staging Queue: Every incoming payload is validated, parsed, and staged immediately into data/received_deliveries.json.
  • Oracle ERP Cloud Dispatch: Staged records are formatted into ERP meter readings and dispatched to Oracle ERP Cloud.
  • Recent Deliveries: The table below displays the last 5 push deliveries received from AVEVA PI with full raw JSON payload inspection.

How Attribute Mapping Works

Map telemetry attributes from your AVEVA PI Asset Framework (AF) databases to corresponding target fields in Oracle ERP Cloud:

  • PI AF Hierarchy Explorer: Browse servers, databases, and elements to select and map attributes directly with one click.
  • Field Mapping: Assign each attribute an Oracle ERP Meter Code (e.g. BLR101_STM_TEMP) and destination value field (readingValue).
  • Transformations: Configure linear multipliers and decimal rounding for unit conversions.
  • Live Payload Preview: Inspect the structured JSON payload dispatched to Oracle ERP Cloud REST API.
  • Storage: All mappings are persisted directly to config/mappings.json.

Pipeline & Connection Settings

Configure AVEVA PI Web API, Oracle ERP Cloud OAuth 2.0 / Basic auth, and schedule interval
How Connection & Authentication Settings Work

Configure and test connections to both endpoints independently:

  • AVEVA PI Web API: Supports Basic Auth, Bearer Token, Windows Integrated (Kerberos/NTLM), or Anonymous. Toggle SSL verification if using plant self-signed certificates. Use the Simulation Mode toggle for offline testing.
  • Oracle ERP Cloud: Supports OAuth 2.0 (Client Credentials Grant) via Oracle IDCS / IAM (recommended) and HTTP Basic Auth. Leave "Enable Transmission" unchecked to keep the pipeline in a safe "Pending connection setup" state while staging data locally.
  • Diagnostics: Use the "Test Connection" buttons on each section to validate reachability and token exchange without triggering a full pipeline cycle.
  • Storage: All configuration is stored directly in config/settings.json.

Step-by-Step Setup in AVEVA PI System Explorer

1. Open Contacts in PI System Explorer

In PI System Explorer, click on Contacts in the bottom-left navigation bar (under Elements / Event Frames / Library / Contacts).

2. Create a New WebService Delivery Endpoint

In the Contacts hierarchy, expand Delivery Endpoints → Right-click and choose New Delivery Endpoint.

3. Enter Parameters (As shown in your PI System Explorer screenshot)

Fill in the Delivery Endpoint properties exactly as below:

PI Parameter Configuration Value Explanation
Name Process Data Name of your delivery contact
Contact Type Delivery Endpoint Default Contact Type
Delivery Channel WebService Native PI AF WebService REST channel
Style REST Lightweight HTTP JSON transmission
Http Method POST Sends payload in request body
URL http://<PIPELINE_HOST>:8000/api/v1/delivery Our pipeline's ingestion endpoint
Content Type application/json JSON formatted body
4. Notification Rule & Payload Format Guarantee

In your Notification Rule's Message / Content configuration, attach your target element attributes (e.g. Level_Sensor, Flow_Rate, Temperature, etc.).

Confirmed Supported Payload Formats

Our pipeline parser automatically detects and normalizes any format PI AF Notifications sends:

  • Standard Nested Format: {"Notification": "...", "Attributes": {"Level": {"Value": 80.5, "UOM": "%"}}}
  • Flat Key-Value Format: {"Notification": "...", "Level_Sensor": 80.5, "Flow_Rate": 120.3}
  • Tag Array Format: [{"Name": "Level_Sensor", "Value": 80.5}, ...]
  • Raw Backup: 100% of the raw delivered payload is saved without alteration into data/received_deliveries.json.
5. Check Ingestion on Dashboard

Whenever a notification triggers, telemetry appears instantly in the Recent 5 Data Received from PI Notifications table on the Dashboard. Click "Inspect Raw JSON" to see the exact payload.

Scheduler & Persistence
Unified cycle frequency for pulling data from PI (in Pull mode) and sending staged data to Oracle ERP (in Endpoint mode)
Unified background execution timer:
  • PI Web API Pull mode: Controls how frequently the engine polls telemetry from AVEVA PI Web API and sends it to Oracle ERP.
  • Delivery Endpoint mode: Deliveries are automatically dispatched to Oracle ERP Cloud immediately upon receipt. Only if an initial dispatch fails (e.g. network outage or ERP temporary error) will the scheduler automatically trigger retries as per this interval setting until successfully delivered.
When checked, incoming PI Notifications are dispatched immediately to Oracle ERP upon receipt, with automatic scheduled retries whenever a transmission fails. When unchecked, incoming records remain staged in data/received_deliveries.json for manual dispatch.
